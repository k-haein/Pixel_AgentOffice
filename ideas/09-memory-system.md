# 메모리 + 지침 시스템 — 사용자 관리 vs 시스템 관리

> 작성: 2026-05-13 (재설계)
> 핵심 원칙: **사용자가 직접 관리하는 것(지침)** 과 **시스템이 자동으로 관리하는 것(메모리)** 을 명확히 분리

---

## 1. 핵심 분리

| | 지침 (Instructions) | 메모리 (Memory) |
|---|---|---|
| **정체** | 캐릭터의 정체성 + 행동 규칙 | 대화에서 쌓인 사실 데이터 |
| **누가 관리** | 사용자가 직접 | 시스템이 자동 |
| **UI 위치** | 책상 위 📝 메모지 클릭 → 모달 | 보통은 비공개 (고급 설정에서 폴더 열기) |
| **저장** | 에이전트 메타데이터 | `data/memories/<agent-id>.md` 파일 |
| **편집 빈도** | 가끔 (필요할 때) | 자주 자동 갱신 |
| **여러명일 때** | 템플릿 공유 가능 | 인스턴스별 독립 |

> 핵심 인사이트: "Mary를 여러명 만들면 메모리를 일일이 관리할 수 없다" → **메모리는 사용자가 신경쓰지 않는 백그라운드 시스템**이어야 함.

---

## 2. 📜 지침 (사용자 관리) — 메모지

### 구조

```
[① 기본 지침] — 채용 시 설정, 읽기 전용
  "당신은 Mary, 꼼꼼한 편집자입니다.
   짧고 또렷한 문장을 선호합니다."

[② 커스텀 지침] — 사용자가 언제든 편집
  "- 반말 금지
   - 비유는 최대 2개까지"
```

### 메모지 UI (책상 위 📝 클릭)

```
┌─ ✍️ Mary의 메모 ────────────────┐
│                                  │
│ [⚙️ 기본 지침]   읽기 전용         │
│ 당신은 Mary, 꼼꼼한 편집자입니다. │
│ 짧고 또렷한 문장을 선호합니다. │
│                                  │
│ [✏️ 커스텀 지침] 사용자 편집       │
│ ┌──────────────────────────┐    │
│ │ - 반말 금지               │    │
│ │ - 비유는 최대 2개         │    │
│ └──────────────────────────┘    │
│                                  │
│       [💾 저장]                  │
│                                  │
│ ─────────────────────────────    │
│ 🔧 고급: [메모리 폴더 열기]       │
└──────────────────────────────────┘
```

→ **메모리는 여기 없음**. 사용자는 지침만 의식.

---

## 3. 🧠 메모리 (시스템 관리) — 백그라운드

### 위치

```
PixelAgentOffice/data/memories/
├─ mary-001.md
├─ mary-002.md   ← 같은 Mary 캐릭터의 다른 인스턴스
└─ haewol-001.md
```

각 직원(인스턴스)당 별도 파일. 같은 캐릭터(Mary)라도 인스턴스가 다르면 메모리 따로.

### 내부 형식

```markdown
# Memory: Mary (mary-001)
# Last updated: 2026-05-13 23:42

## 사용자 정보
- 이름: 해인
- 글쓰기 스타일: 짧고 또렷한 문장 선호

## 작업 이력
- "새벽의 도서관" 단편 편집 (v3까지)
- 비유는 최대 2개로 제한 (사용자 요청)

## 자주 나온 주제
- 새벽, 침묵, 도서관, 책의 향기
```

### 사용자 시각

- **보통은 의식 안 함**. 시스템이 알아서 채움.
- "고급 → 메모리 폴더 열기" 누르면 .md 파일들 보임.
- 직접 편집도 가능 (텍스트 파일이라).
- 백업/내보내기/삭제는 파일 단위로 가능.

## 4. 매 API 호출 시 합쳐서 전송 (기술적 흐름)

UI에선 분리돼있지만, Claude에 보낼 때는 합쳐짐:

```
[Claude에 보내는 system prompt]

# 정체성
당신은 Mary, 꼼꼼한 편집자입니다.
짧고 또렷한 문장을 선호합니다.

# 규칙
- 반말 금지
- 비유는 최대 2개까지

# 사용자 정보 (메모리)
- 이름: 해인
- 작업 중: "새벽의 도서관" v3
- 직역 우선
```

→ Claude 입장에선 다 "지침"으로 보이지만, **앱 UI에서 분리**된 채로 관리.

## 5. 채팅 영속화 + 보존 버퍼

```
[3단 저장 모델]

┌─ 메모리 파일 (.md) ──────────┐   ← 압축된 장기 데이터
│ 사용자 정보·선호·이력          │      시스템이 자동 갱신
└─────────────────────────────┘
              ↑ 압축
┌─ 보존 버퍼 (raw 메시지) ─────┐   ← 최근 N개 그대로
│ 최근 채팅 보존                │      자동 (시스템)
└─────────────────────────────┘
              ↑ 매 채팅 후
┌─ 현재 채팅 (활성) ──────────┐   ← 진행 중
│ 새 메시지들                  │
└─────────────────────────────┘
```

**보존 버퍼** (설정 가능):
- 기본: **인스턴스당 최근 50 메시지** 또는 **14일**
- 초과분만 메모리로 압축
- → 메모리 갱신 미뤄도 최근 N개는 절대 안 사라짐

---

## 6. 메모리 갱신 모드 (시스템 동작 방식)

| 모드 | 동작 | 비용 | 추천 |
|---|---|---|---|
| ⚙️ **OFF** | 메모리 시스템 비활성. 보존 버퍼만 (자연 삭제) | 0 | 일회성 사용자 |
| ✋ **MANUAL** | Ctrl+S 시에만 갱신 | 그때만 | 정밀 제어 좋아함 |
| 💬 **ASK** | 야간 시작 전 미리보기 → 확인 | 채팅당 1회 | 신중한 사용자 |
| 🤖 **AUTO** ⭐ | 야간 자동 압축, 다음날 토스트 | 채팅당 1회 (조용히) | 기본 권장 |

→ **기본값 AUTO**. 사용자는 메모리를 의식할 필요 없음.

---

## 7. 🌙 시간대 통합

### 토큰 = 회사 전체 자원
- 사무실 **상단 토큰 바** UI 하나가 전체 상태 표시
- 80% → 노란색
- 95% → 빨간 흔들림
- 0% (한도 도달) → **밤 도래** → 전체 사무실 컴퓨터 OFF

### 메모리 압축 = 직원 개별 (밤에 자동)
- 밤이 되면 각 직원의 보존 버퍼 초과분이 메모리로 압축
- 사용자에겐 보통 알림 없음 (조용히)
- AUTO 모드에서 다음날 아침에 토스트 "Mary가 어젯밤 메모 정리"

## 8. 🧠 에이전트별 모델 설정

각 인스턴스마다 별도 모델:

```
┌─ ✍️ Mary 설정 ────────────────────┐
│ 대화 모델:                          │
│   ● Sonnet ⭐                       │
│   ○ Opus / ○ Haiku                 │
│                                    │
│ 메모리 갱신 모델:                    │
│   ● Haiku ⭐ (비용 절감)             │
│   ○ Sonnet                         │
│                                    │
│ 메모리 모드:                         │
│   ● AUTO ⭐                          │
│   ○ OFF / ○ MANUAL / ○ ASK         │
│                                    │
│ 보존 버퍼:                          │
│   메시지 수: [50    ]                │
│   기간:      [14일  ]                │
└────────────────────────────────────┘
```

## 9. 같은 캐릭터 여러 인스턴스 — Mary x N

| 시나리오 | 처리 |
|---|---|
| Mary 캐릭터 템플릿 (기본 지침) | 1개 (공유) |
| 사용자가 Mary 3명 채용 | 3개 인스턴스 (`mary-001`, `mary-002`, `mary-003`) |
| 각자 커스텀 지침 | 독립 (사용자가 따로 설정) |
| 각자 메모리 | 독립 (`mary-001.md` ~ `mary-003.md`) |
| 각자 대화 기록 | 독립 |

→ "회사에 마리 3명이 일하고 각자 다른 일 함" 시나리오 가능.

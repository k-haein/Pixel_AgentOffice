## 🏗 사무실 구조 — 박스/벽/창문 (P1)

사용자 명시 구조:

```
┌────────────────────────────────┐
│   [창문 — 풍경 + 날씨]              │
├────────────────────────────────┤
│   [기본 설명 / 시계 / 토큰 보드 액자]   │
├────────────────────────────────┤
│   사무실 전체                       │
│   · 사장석                         │
│   · 팀 A (B/C는 활성화 시)           │
│   · 책상 / 가구                    │
└────────────────────────────────┘
```

### 16. 사무실 영역 박스
- 사무실 전체에 명확한 외곽선 (벽). 사장실은 별도 박스 또는 윗쪽 영역으로 구분
- 시계·토큰 보드는 *벽에 액자처럼* 부착 (벽 안쪽 위쪽 띠)

### 17. 창문 키우기 + 풍경
- 현재 sky band (16px 높이)가 너무 좁음
- 확대 → **풍경 픽셀**: 건물 / 산 / 도로 / 차 (다 안 보여도 OK, 회사 밖 풍경 + 날씨)
- 시간대별 풍경 색 + 구름 / 비 / 눈 (날씨)

### 18. 벽 영역 신규
- 사무실 위쪽 띠 = 벽 (베이지/연갈색)
- 액자 — 시계 / 토큰 보드 / 캘린더(추후) 부착 가능

## 👥 팀 시스템 변경 (P0 — 큰 작업)

### 19. 활성 팀만 표시
- **현재**: 팀 A·B·C 16자리 모두 항상 보임
- **변경 후**: 팀원 *최소 1명* 있는 팀만 표시. 빈 팀은 숨김.
- **초기 상태**: 팀 A만 (기본 1팀)

### 20. 팀 추가 버튼
- 사용자가 "팀 추가" 버튼 클릭 시 새 팀 영역 생성 (최대 3)
- 버튼 위치 — topbar `+ 채용` 옆? 또는 사무실 안 floating?

### 21. 빈 자리 — 채용 시에만 보임
- **현재**: 빈 자리 항상 옅게 표시 (alpha 0.55)
- **변경 후**: 평소엔 빈 자리 안 보임. **채용 버튼 누른 *순간*에만** 빈 자리 투명하게 보여서 "여기에 배정 가능" 안내. 사용자가 알아서 자리 선택.

### 22. 드래그 이동 — 활성 팀 안에서만
- 자리 이동 드래그할 때 빈 자리는 *생성된 팀* 안에서만 보이게
- 즉 팀 2개 활성이면 그 2개 팀의 빈 자리만

### ❓ 모호한 점 (사용자 확인 필요)
- **기존 데이터**: 현재 store에 저장된 직원의 seatId가 `leader:B`, `member:B:0` 등이면? **임시 처리**: 마이그레이션으로 `member:A:N`으로 재배치
- **팀 추가 버튼 위치**: topbar 옆 vs 사무실 안 floating
- **팀 삭제**: 팀에 직원이 0명 되면 자동 숨김? 또는 사용자가 "팀 삭제" 명시? **임시 처리**: 자동 숨김 (마지막 한 명 떠나면 팀 사라짐)
- **사장석**: 사장석은 팀과 무관 — 항상 1자리 별도 표시 OK?

→ **현재 우선순위**: "지금부터 임의로 감춰줘" (사용자 명시) — 코드에서 *팀 B, C는 모두 숨기고 팀 A만 표시*. 기존 데이터는 임시로 A로 마이그레이션. 추후 팀 추가 버튼 등으로 확장.

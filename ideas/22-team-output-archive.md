## 발단 — "2층을 만드는 게 아니라 여기서 에이전트 기능을 추가하는 게 맞나?"

웹 데모(mock)로 2층 팀 작업을 처음 눈으로 확인한 직후 나온 질문이다.
UI는 잘 도는데 **뭔가 허전하다**는 감각이 있었고, 그 정체를 파보니 이랬다.

### 지금 팀 작업이 실제로 하는 일

`electron/main.ts`의 `agent:run-team` 핸들러가 에이전트에게 쥐여주는 도구:

```js
leaderTools: [getCurrentTimeTool],
memberTools: [getCurrentTimeTool],
```

`get_current_time` **하나**. 그것도 `agent/tools/time.ts` 주석에 *"Phase 2 루프 검증용"*이라 명시된 확인용 도구다.

그래서 팀 작업의 실체는:

> 팀장이 팀원에게 지시 → 팀원이 **글을 써서** 보고 → 팀장이 그 글을 **종합해서** 보고

**아무것도 실제로 되지 않는다.** 문장이 두 번 생길 뿐이다.
포폴 방문자가 30초 만져보고 *"결국 채팅에 단계만 늘린 거네"* 라고 느낄 지점이 정확히 여기다.

---

## 기각한 안 — "진짜 도구를 붙이자"

파일 읽기/쓰기, 웹 검색, 코드 실행 같은 실제 도구를 붙이는 방향. **기각.**

| | 웹 데모 (브라우저) | Electron 앱 |
|---|---|---|
| 파일 읽기/쓰기 | ❌ 불가 | ⭕ |
| 웹 검색 | ❌ 서버 없어 불가 | ⭕ |
| 코드 실행 | ❌ 불가 | ⭕ |
| **누가 보는가** | **포폴 방문자 전원** | 사실상 아무도 |

기각 근거 3가지:

1. **포폴 가치는 전부 웹 데모에 있다.** 링크 하나로 보여주는 것. 그런데 진짜 도구는 웹에서 전부 죽는다 → exe 받고 키 발급한 사람만 볼 수 있는 기능이 된다.
2. **차별점이 안 늘어난다.** 도구 실행은 CrewAI도 Claude Code도 훨씬 잘한다. 이 프로젝트의 킥은 *"도구를 잘 쓴다"*가 아니라 **"위계를 공간으로 표현한다"**(PRD v0.0.3 §2.2)다. 도구를 붙여도 그 축은 안 강해진다.
3. **제품화 중단 결정(PRD §8.3)과 어긋난다.** 며칠짜리 투자를 회수할 곳이 없다.

## 채택 방향 — 빠진 건 도구가 아니라 **결말**이다

현재 흐름을 그려보면 은유가 중간에 끊긴다.

```
의자에 앉힌다 → 조직도가 된다 → 일을 시킨다 → 위임된다 → …텍스트가 뜬다 → 사라진다
     ↑ 공간            ↑ 공간         ↑ 공간        ↑ 공간      ↑ 여기서 공간을 벗어남
```

**입력은 공간인데 출력이 채팅창이다.**

### 제안: 결과물 보관함

팀 작업이 끝나면 결과가 **사무실 안에 문서로 쌓인다.** 캐비닛이든 게시판이든.
클릭하면 열리고, **누가 · 언제 · 어떤 작업을 했는지** 남는다.

### 왜 도구 추가보다 나은가

1. **웹 데모에서 100% 동작한다** — 문서는 브라우저 안에 남으면 된다. 서버도 파일시스템도 불필요
2. **킥이 완성된다** — 입력도 공간, 출력도 공간. 은유가 끝까지 간다
3. **GIF에 결말이 생긴다** — 지금은 "카드가 ✅로 바뀜"에서 끊기는데, "문서가 캐비닛에 꽂힘"까지 가면 이야기가 닫힌다
4. **하루면 된다** — 동결 결정을 깨지 않는 규모

## 설계 스케치 (미확정)

### 데이터

```ts
type TeamOutput = {
  id: string
  createdAt: string        // ISO
  leaderId: string
  leaderName: string       // 스냅샷 — 나중에 해고돼도 기록은 남게
  team: TeamId
  task: string             // 사장이 내린 지시
  report: string           // 팀장 최종 종합 보고
  delegations: {           // 팀원별 위임 내역
    memberId: string
    memberName: string
    instruction: string
    report: string
    isError: boolean
  }[]
  usage: { inputTokens: number; outputTokens: number }
}
```

- 저장: `app-data.json`에 `teamOutputs: TeamOutput[]` 추가 (Electron) / mock은 메모리 또는 localStorage
- **이름을 스냅샷으로 저장**하는 이유: 직원을 해고해도 "누가 했는지"가 남아야 기록으로서 의미가 있다

### 화면

- **가구로 배치** — 상점의 캐비닛/책장/게시판 중 하나를 "보관함"으로 승격. 사무실에 실제로 서 있는 오브젝트
- 팀 작업 완료 시 **문서가 보관함으로 날아가는 연출** (캐릭터 연출과 같은 계열)
- 보관함 클릭 → 목록 모달 (최신순, 팀·팀장·날짜 표기) → 항목 클릭 → 상세(지시 / 위임 내역 / 최종 보고 / 토큰)
- 빈 상태: *"아직 보관된 결과물이 없어요. 팀장에게 일을 시켜보세요."*

### 열린 질문

- [ ] 보관함은 **기본 배치**인가 상점 구매인가? (기본 배치가 나을 듯 — 구매를 거치면 데모 방문자가 못 봄)
- [ ] 1층 개인 채팅 결과도 보관 대상인가? (아니오 쪽 — 팀 작업 전용이어야 "위임의 결말"이라는 의미가 선명)
- [ ] 보관 한도는? (50건 정도 링버퍼 / 삭제 기능)
- [ ] 내보내기(.md 다운로드)를 붙일까? — 웹에서도 되지만 포폴 가치는 크지 않음. 보류

## 우선순위

**웹 데모 배포 다음.** 배포로 URL이 생겨야 이걸 만들어도 보여줄 데가 있다.

| 순위 | 할 일 | 비용 |
|---|---|---|
| 1 | 웹 데모 배포 (시드 + localStorage + Actions) | 반나절 |
| 2 | 위임 연출 (팀장→팀원 화살표) — GIF 소재 | 반나절 |
| 3 | **결과물 보관함 (본 문서)** | 하루 |
| ❌ | 실제 도구 (파일·웹검색) | 기각 (위 참조) |

> ⚠️ 2·3번은 **"포폴이 더 잘 팔리게 하는 것"**이지 제품을 향한 게 아니다.
> 제품화 중단 결정(PRD v0.0.3 §8.3)은 유효하다. 1번만 하고 멈춰도 포폴로는 성립한다.

# UI 렌더링 옵션 3가지 — 시각적 비교 + 결정 자료

> 작성: 2026-05-12
> 목적: 같은 사무실 레이아웃을 3가지 방식으로 구현했을 때 무엇이 달라지는지 비교
> 결정: 동일한 시각 결과를 낼 수 있다면, "개발 난이도 / 애니메이션 유연성 / 인터랙션 용이성"으로 판단

---

## 공통 전제

세 옵션 모두 같은 사무실 레이아웃을 그릴 수 있음:
- 한 화면에 모든 부서 보임
- 리더 최상단 사장석
- 부서별 클러스터
- 책상 + 명패 + 에이전트 캐릭터 + 상태 표시

**시각적 결과만 보면 큰 차이 없음.** 진짜 차이는 **"움직임을 얼마나 자연스럽게 구현할 수 있는가"** + **"코드 작성/유지보수의 용이성"**.

---

## 옵션 1: Phaser.js ⭐ (추천)

### 기본 컨셉
HTML5 기반 2D 게임 엔진. Scene/Sprite/Tween 같은 게임적 개념을 그대로 제공.

### 시각 예시
- Office mockup 정도의 화면을 **거의 비슷한 양의 코드**로 구현 가능
- 차이점: 일하는 애니메이션(머리 까딱, 책상 위 파일 회전, 말풍선 통통) 같은 **부드러운 게임적 모션**이 쉬움
- 캐릭터를 8x8 또는 16x16 픽셀 스프라이트로 만들면 진짜 게임 같음

### 외부 참고
- 공식 예제: https://phaser.io/examples (사이드뷰 / 탑다운 / 픽셀 등 카테고리)
- AI Town 같은 픽셀 사무실/마을 데모가 이 류의 엔진으로 제작됨

### 장점
- 스프라이트 애니메이션 (idle, walk, work 등) 프레임 전환이 한 줄
- 트윈(부드러운 이동/페이드) 내장
- 입력 처리 (클릭/더블클릭/드래그) 정형화됨
- Phase 1.5의 자율 시뮬레이션 (에이전트가 사무실 안에서 돌아다니거나 옆 책상으로 이동) 시 거의 게임처럼 구현 가능

### 단점
- 학습 곡선 살짝 있음 (Scene/Sprite/Group 개념)
- React DOM과 분리됨 → 채팅창 UI는 React로, 사무실 씬은 Phaser로 분리하는 구조 필요 (오히려 깔끔하긴 함)

### 적합도
- 학습 목적 ✅ (게임 엔진 경험)
- 픽셀 사무실 ✅
- 미래 자율 시뮬레이션 ✅✅
- 코드량/관리 부담 🟡 (중간)

## 옵션 2: PixiJS

### 기본 컨셉
초고속 2D 렌더러. Phaser보다 "한 단계 낮은 레이어" — 게임 엔진 기능(씬/입력/물리)은 직접 만들어야 함.

### 시각 예시
- Phaser와 **시각적으로 동일**하게 만들 수 있음
- 한 화면에 수천 개 객체를 렌더링해도 빠름 (이 프로젝트엔 오버스펙)

### 외부 참고
- 공식 쇼케이스: https://pixijs.com/8.x/examples

### 장점
- 매우 빠르고 가벼움
- 커스텀 셰이더 등 고급 기능 가능

### 단점
- "씬 관리, 입력 처리, 애니메이션 헬퍼" 등을 **직접 구축**해야 함
- 같은 결과 만드는데 Phaser보다 코드량 많음

### 적합도
- 우리 규모(책상 ~20개)엔 오버스펙
- 학습 목적이라도 굳이? — Phaser로 게임 엔진 개념 익히는 게 더 일반적

→ **이 프로젝트에선 비추천.** Phaser가 같은 일을 더 적은 코드로 해줌.

## 옵션 3: 순수 React + CSS (HTML DOM)

### 기본 컨셉
지금 만든 `office-mockup.html` 방식. 책상/캐릭터 모두 `<div>`로 그리고 CSS로 스타일링.

### 시각 예시
- **mockup이 바로 이 방식.** 한번 열어보면 정확히 이 결과
- 픽셀 아트 느낌은 `image-rendering: pixelated` + 단색 박스 + 한정 팔레트로 충분히 흉내 가능

### 장점
- React 컴포넌트 그대로 → 채팅창/툴팁/뱃지 등 UI 통합 쉬움
- CSS 트랜지션·애니메이션으로 간단한 모션 OK (호버 확대, 말풍선 깜빡임 등)
- 의존성 최소, 디버깅 쉬움
- 텍스트(이름표) 처리 깔끔

### 단점
- **복잡한 게임적 애니메이션은 한계** — 스프라이트 시트 사용·캐릭터 걸어다니기 등은 매우 까다로움
- DOM이 많아지면(에이전트 100명+) 느려질 수 있음 (우리 규모엔 문제없음)
- 자율 시뮬레이션에서 캐릭터들이 자유롭게 돌아다니는 그림은 잘 안 어울림

### 적합도
- Phase 1 mockup ✅ (이미 만든 상태)
- Phase 1 본격 구현 🟡 (애니메이션 한계)
- 자율 시뮬레이션 ❌

## 결론

| 항목 | Phaser | PixiJS | React+CSS |
|---|---|---|---|
| 픽셀 사무실 정적 화면 | ✅ | ✅ | ✅ |
| 단순 상태 변화 (working ↔ idle) | ✅ | ✅ | ✅ |
| 캐릭터 스프라이트 애니메이션 | ✅✅ | 🟡 (직접 구현) | ❌ |
| 캐릭터가 돌아다님 (자율 시뮬) | ✅✅ | 🟡 | ❌ |
| 코드량/난이도 | 🟡 중 | 🔴 많음 | 🟢 적음 |
| React UI 통합 | 🟡 (분리 필요) | 🟡 | ✅ |
| 학습 가치 | 게임 엔진 경험 | 저수준 렌더러 | 보편적 |

### 추천 전략 — **하이브리드**

1. **사무실 씬(canvas)** = Phaser
   - 책상, 캐릭터 스프라이트, 일하는 애니메이션, 자율 이동
2. **UI 오버레이(DOM)** = React
   - 채팅 팝업, 메뉴, 사이드 패널, 명패 텍스트, 모달

Phaser canvas 위에 React 컴포넌트를 absolute 위치로 띄우는 구조. 둘이 싸우지 않음.

### 빠른 시작 팁

- **현재 mockup(React+CSS 방식)** 그대로 두고 → 첫 프로토타입 1주일 정도 검증
- Phase 1 본격 진입 시 사무실 영역만 Phaser로 교체
- 즉 mockup은 버리지 않고 **"기능 명세서" 역할**로 계속 활용

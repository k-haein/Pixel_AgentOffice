# PixelAgentOffice — 기획 케이스 스터디

> **에이전트 위계를 코드가 아니라 좌석 배치로 정의할 수 있는가** — 픽셀 사무실 형태로 만들어 검증한 UX 실험. 기획 + 코드 + 시각 산출물 아카이브.

**Status**: **v0.0.3** — 2층(멀티 에이전트 팀 협업) 트랙 완주. 핵심 인터페이스 "좌석 = 조직도" 정립 후 **제품화 중단 결정**([근거](v0.0.3/PRD.md)) → 포트폴리오 자산으로 정리 중.
**Period**: 2026-05-12 (기획+M1) → 2026-07-09 (2층 완주) · 이후 동결
**Stack**: Electron + React 19 + Phaser 4 + TypeScript + Vercel AI SDK (Claude·Gemini·GPT) + Playwright + vitest

## 💡 해결하려는 문제

AI 에이전트는 강력하지만 일반 사용자에겐 **진입 장벽이 높습니다** (YAML/JSON 정의, 터미널, 추상적 오케스트레이션). 그런데도 많은 사람이 ChatGPT/Claude에서 "페르소나 채팅"(편집자·칸트·작가)을 일상적으로 씁니다. → **그 행동을 게임형 워크스페이스로** 옮긴 게 이 프로젝트입니다.

| 기존 도구 | PixelAgentOffice |
|---|---|
| **위계 정의 = 코드/YAML** | **의자에 앉힌다** ★ |
| **위임 권한 = `allow_delegation=True`** | **과장 진급** — 신뢰 축적의 결과 ★ |
| 에이전트 정의 = 코드/설정 | 캐릭터 선택 + 이름 + MBTI |
| 상태 모니터링 = 로그 | 사무실 둘러보기 + 감정 이모지 + 위임 카드 |
| 에러 = 빨간 메시지 | 직원이 시무룩 / 친절 한글 안내 |

★ 두 줄이 이 프로젝트의 진짜 발명품입니다. CrewAI·AutoGen에는 위계가 있지만 전부 코드이고, Claude Projects·Custom GPTs에는 위계 자체가 없습니다. **"위계가 있으면서 코드가 아닌" 자리가 비어 있습니다.** 상세: [v0.0.3 PRD §2.2](v0.0.3/PRD.md)

## 🔍 기획 과정에서 자랑스러운 순간

1. **제약이 결정을 명확하게** — "배포 자동화 필요" → Python 탈락 → Electron 채택
2. **사용자 인사이트가 아키텍처를 단순화** — "동생은 페르소나 채팅 쓴다" → 이중 모드 → Phase 1 단순화
3. **에러를 폴리시로 격상** — 토큰 고갈 → 강제 야간 시그니처
4. **재미를 개성으로** — 12종 감정 이모지 + MBTI 16종 페르소나 (Day 12)
5. **실배포로 검증 진입** — portable EXE v0.0.1 → 외부 테스터 피드백 사이클
6. **정직한 상태 추적** — 완성/부분구현/계획을 구분하고 미완 기능을 명시 (PRD §4.2)
7. **"만들어보고 안 하기로 결정"** — 2층까지 완주한 뒤 제품화하지 않기로 판단하고, 그 근거를 문서에 남김 (PRD §8.3)

## 📌 이 케이스 스터디에 대해

발전 과정을 버전 폴더로 보존합니다. **v0.0.0**은 단일 세션 기획 결과물(Day 1~7), **v0.0.1**은 1차 배포본(Day 12), **v0.0.2**는 성장 루프·온보딩·테스트 그물까지 갖춘 2차 배포본(Day 14), **v0.0.3**은 2층 팀 협업까지 완주한 뒤 핵심 인터페이스를 정립하고 제품화 중단을 결정한 최종본입니다.

기획이 코드·배포까지 이어진 흐름과, **그 끝에서 "이 방향은 하지 않는다"고 판단한 근거**가 함께 남아 있습니다. 후자가 이 케이스 스터디에서 가장 보여드리고 싶은 부분입니다.
